# CrossRoad CRM — نظام إدارة الشركة الكامل

نظام حقيقي PHP + MySQL بصلاحيات مطبقة من الـ Backend. الملفات:

| الملف | الوظيفة |
|---|---|
| `index.php` | الواجهة الكاملة (تسجيل دخول + كل الأقسام) |
| `api.php` | الـ Backend الموحد — كل التحقق من الصلاحيات هنا |
| `db.php` | إنشاء الجداول تلقائيًا (Migration آمنة) + البيانات المبدئية |
| `config.php` | **الملف الوحيد اللي هتعدله** — بيانات قاعدة البيانات |
| `wa_webhook.php` | استقبال رسمي لرسائل WhatsApp Cloud API → Leads تلقائية |
| `.htaccess` | حماية ملفات الإعدادات من الفتح المباشر |
| `uploads/` | مرفقات المهام (محمية من تنفيذ PHP) |

---

## خطوات الرفع على Hostinger (أسهل طريقة — بدون تعديل أي ملف)

1. من hPanel → Databases → Management → اعمل قاعدة بيانات + مستخدم (لو لسه)
2. File Manager → public_html → ارفع الـ ZIP → Extract
3. افتح في المتصفح: **https://موقعك.com/install.php**
4. حط بيانات القاعدة (المعالج بيختبرها لحظيًا وبيقولك الغلط فين بالعربي وبيكتب config.php بنفسه)
5. اختار اسم المستخدم وكلمة المرور بتوعك أنت — وخلاص، المعالج بيحذف نفسه تلقائيًا وتدخل على طول

## الطريقة اليدوية البديلة (5 دقائق)

**1) إنشاء قاعدة البيانات:**
- من hPanel → **Databases → MySQL Databases**
- اعمل Database جديدة + User جديد واربطهم ببعض (All Privileges)
- هتاخد منها 3 قيم: اسم القاعدة، اسم المستخدم، كلمة المرور (بيبدأوا عادة بـ `u123456789_`)

**2) تعديل `config.php`:**
افتح الملف وحط القيم الثلاثة مكان الـ placeholders. لو النظام هيتحط في فولدر فرعي مفيش أي تعديل تاني مطلوب.

**3) الرفع:**
- File Manager → `public_html` (أو فولدر فرعي زي `public_html/crm`)
- ارفع الـ ZIP واعمله **Extract**

**4) أول تشغيل:**
- افتح الرابط — **الجداول هتتعمل تلقائيًا** أول مرة (مفيش SQL يدوي)
- سجّل دخول بالحساب المبدئي:
  - المستخدم: `owner`
  - كلمة المرور: `ChangeMe@123`
- **النظام هيجبرك فورًا تغيّرها** قبل ما تشوف أي صفحة. بعدها الحساب المبدئي مبقاش موجود بكلمة السر دي في أي مكان.

**5) بعد الدخول:**
- المستخدمون والصلاحيات → أضف موظفينك (كل واحد بياخد باسورد مبدئية وبيتجبر يغيّرها أول دخول)
- الإعدادات → فعّل اللي يناسبك: منع الموبايل / الأجهزة المعتمدة / حصر الحضور في IP الشركة

## الحساب المبدئي وسياسة كلمات المرور
- لا توجد أي كلمة مرور مكتوبة في HTML أو مرئية في الـ Source أو بترجع من الـ API.
- كل كلمات المرور متخزنة **bcrypt hash** — حتى أنت كمدير مش هتشوف باسورد حد، بس تقدر تعيّن واحدة جديدة.
- تغيير باسورد أي مستخدم بيسجّل خروجه من كل الأجهزة تلقائيًا.
- "تذكرني" بتشتغل بـ Token منفصل صالح 30 يوم وبيتلغي مع "خروج من كل الأجهزة".

## سياسات الأجهزة والحضور (من الإعدادات)
- **منع الموبايل:** بيتفحص على السيرفر من الـ User-Agent، مش JavaScript — تصغير الشاشة مش بيعدّيه. الـ owner مستثنى افتراضيًا.
- **الأجهزة المعتمدة (الأقوى):** لما تفعّلها، أي جهاز جديد بيحاول يدخل بيتسجل في قسم "الأجهزة" ويترفض دخوله لحد ما تعتمده بضغطة. دي الضمانة الحقيقية ضد الدخول من بره الشركة.
- **حصر الحضور في IP:** اكتب بداية IP الشركة (مثال `156.220.`) وتسجيل الحضور هيترفض من أي شبكة تانية.
- محاولات الدخول المرفوضة كلها بتتسجل (login_attempts + سجل النشاط).

## WhatsApp — الوضع الحالي والترقية
- **شغال فورًا بدون أي إعداد:** كل رقم في صفحة Leads جنبه زر بيفتح المحادثة في WhatsApp، وزر Lead جديد بيتأكد إن الرقم مش متسجل قبل الإضافة.
- **الترقية الرسمية (WhatsApp Cloud API):** من Meta for Developers اعمل App + فعّل WhatsApp، وحط في إعدادات الـ Webhook عندهم:
  - Callback URL: `https://موقعك/wa_webhook.php`
  - Verify Token: منسوخ من صفحة الإعدادات جوه النظام
  - Subscribe على `messages`
- بعدها أي رسالة على رقم الشركة بتتحول **Lead تلقائيًا** (بدون تكرار لو الرقم موجود كـ Lead أو عميل).
- ⚠️ متستخدمش أي أداة "WhatsApp Web bot" غير رسمية — بتعرض رقم الشركة للحظر.

## النسخ الاحتياطي
- من hPanel → **Databases → phpMyAdmin** → اختر القاعدة → **Export** (ملف SQL واحد فيه كل حاجة).
- Hostinger بياخد Backups أسبوعية تلقائية برضه من hPanel → Backups.
- المرفقات: فولدر `uploads/` انسخه مع الـ SQL.

## الاختبارات
تم اختبار النظام آليًا بـ **87 سيناريو** end-to-end ناجحين، تغطي: الدخول والأمان وCSRF، إجبار تغيير الباسورد، منع الموبايل، الأجهزة المعتمدة، دورة الإجازة كاملة (طلب → ظهور للإدارة → موافقة/رفض → إشعار → سجل → منع التكرار ومنع الاعتماد الذاتي)، فلوس الـ Owner (منع الموظفين على مستوى الـ API + CRUD + سلة)، الحضور (منع التكرار + تعديل بسبب إجباري)، المهام (رؤية الموظف لمهامه فقط + القيم الثلاثة بصلاحياتها + تسجيل تعديل القيمة بالقديم والجديد)، العملاء (البيانات المالية لا تُرسل أصلًا في response الموظف)، الـ Leads (منع التكرار + التحويل مرة واحدة)، السلة (استرجاع + حذف نهائي للـ Super Admin فقط)، والـ Webhook.


## الجديد في هذا الإصدار (v2)
- **داشبورد غنية:** حضورك + كروت حسب دورك + تجديدات الويب الحمراء + عقود CRM اللي هتتجدد + دفعات متأخرة + توزيع المهام على البورد + أقرب استحقاقات مهامك.
- **دفعات العملاء مربوطة بالحسابات:** من ملف أي عميل سجّل دفعة (مدفوعة أو مستحقة بتاريخ). المدفوعة بتنزل **تلقائيًا** كإيراد في حسابات الشركة، والمستحقة المتأخرة بتظهر بتحذير. جدول العملاء فيه عمود "المحصَّل" وإحصائيات فوقه: إجمالي، نشطين، MRR، محصَّل، مستحق، متأخر.
- **حسابات الشركة (قسم جديد منفصل عن فلوسك الخاصة):** إيرادات (تلقائية من الدفعات + يدوية) ومصاريف بتصنيفات، داشبورد بصافي ربح ونسبة تحصيل ورسم 6 شهور. صلاحيتها `company_finance` — تقدر تديها للمحاسبة من غير ما تشوف فلوسك الشخصية.
- **الرواتب:** حدد راتب كل موظف من صفحة المستخدمين (حقل سري لأصحاب الصلاحية فقط)، وزر "صرف رواتب الشهر" بيعرض الكل، تعدّل أي مبلغ بملاحظة (خصم/حافز) وتعتمد — بتنزل بنود مصاريف تلقائيًا، ومنع صرف نفس الشهر مرتين.
- **عملاء تجديد (قسم جديد):** اسم، رقم، لينك الموقع، تاريخ التجديد، قيمة اختيارية. أي عميل باقي على تجديده ≤30 يوم بيظهر بتحذير 🔴 أحمر في القسم والداشبورد وبادج على القائمة الجانبية.
